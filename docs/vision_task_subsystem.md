# K230视觉与任务控制子系统实施状态

本项目采用“电脑端工程配置 + K230现场执行 + STM32实时运动控制”的三层架构。电脑端负责精细模板建立、批量验证、标定文件生成和部署包制作；K230负责采图、识别、姿态、抓取点、坐标转换、任务管理与UI；STM32负责确定性运动、真空、I/O及安全联锁。

## 已固定的核心接口

- `TargetRecord`：模板身份、像素中心、角度、置信度、旋转框、抓取点、质量标志和机械坐标。
- `DetectionResultRecord`：`scan_id`、`view_id`、帧号、轴位置快照、图像质量、目标列表和版本信息。
- `Recipe`：相机、分割、匹配、吸头、标定、排序和重拍配方引用。
- 质量位标志：触边、疑似重叠、抓取区域不足、低置信度、不可达、重复、尺寸异常、图像质量异常和模板冲突。

质量位标志定义在 `shared_protocol/target_flags.py`，该文件不依赖 NumPy 或 OpenCV，可同时复制到 K230 和 STM32 协议测试程序中。任一阻断位存在时，`auto_pick_allowed=false`。

## 抓取点规划

电脑端在导出K230模板时对二值掩膜执行距离变换，并提取相互分离的局部极大值：

1. 主抓取点是距外轮廓和内部孔洞最远的有效点；
2. 最多保存两个候选抓取点；
3. 每个点保存像素坐标、安全半径和相对得分；
4. K230根据当前目标的旋转角和尺度，将模板抓取点转换到实时画面；
5. 安全半径不足、触边或模板冲突时禁止自动抓取。

模板元数据保留旧版 `pick_point_xy` 和 `pick_radius_px` 字段，同时新增 `pick_points` 和 `pick_planning`，旧部署包仍可加载。

## 平面标定

`industrial_segpose.calibration.PlanarCalibration`支持：

- 4点及以上像素—局部机械坐标拟合；
- 可选RANSAC；
- 像素坐标转局部毫米坐标；
- 叠加拍照时轴位置快照与相机—吸头偏置，输出全局机械坐标；
- 平均误差、P95误差、最大误差和逐点误差；
- 带SHA-256校验的JSON标定文件。

正式验收建议使用25个覆盖全视野的标定点。镜头、相机位置或料面高度变化后必须重新标定。

电脑端主界面提供“相机—机械坐标标定”入口。点位文件格式参考`configs/calibration_points.example.json`，输出目录包含：

- `calibration.json`：K230可部署的矩阵、偏置、误差统计和SHA-256校验；
- `calibration_points.csv`：每个点的期望值、预测值和误差；
- `calibration_report.md`：平均、P95和最大误差摘要。

若标定工具输出到项目根目录的`calibration/`，生成K230部署包时会先校验文件并仅复制`calibration.json`。确认现场标定有效后，将设备配置中的`calibration.enabled`设为`true`。当前`axis_snapshot_mm`仍是静态调试值；进入STM32联调后必须由每次拍照请求携带的真实轴位置快照替代，禁止把静态值用于自动抓取。

## K230图像质量门控

板端使用全图LAB亮度统计、局部对比度和九宫格亮度差异进行低分配质量检测。默认行为为：

1. 合格帧进入目标检测并显示`QUALITY:OK`；
2. 坏帧不产生新目标，连续读取下一帧作为重拍；
3. 超过`maximum_retries`后显示`QUALITY:ALARM`；
4. 后续任一合格帧会自动解除报警；
5. 状态变化写入限长轮转日志，心跳携带完整质量报告。

阈值位于`device_config.json`的`quality_gate`节点，现场应在固定照明完成后使用真实样料标定。该轻量方法不复制完整图像，适合K230有限内存环境。

## 后续阶段

1. 在真实K230采集图像上标定质量阈值，并补充运动模糊专项验证。
2. 将已验证标定文件加载到K230实时目标输出，并接入STM32轴位置快照。
3. 冻结STM32二进制协议，增加CRC16、序号、ACK/NACK、超时重发和心跳状态机。
4. 开发扫描批次、视场合并、全局去重、排序和抓取反馈状态机。
5. 完成每类100件识别测试、25点定位测试、异常注入和8小时连续运行。
